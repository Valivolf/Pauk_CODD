# Робот Яндекс.Конструктора карт

Отдельный контейнер `yandex-robot` (Chromium + Playwright). Ведёт карты бригад в
[Конструкторе карт Яндекса](https://yandex.ru/map-constructor/) тем же способом, что и человек, и кладёт
ссылку на карту в поле «Ссылка на карту» бригады (его видит и монтёр в боте).

## Что делает сам

Фоновый цикл приложения (`app/services/yandex_map_sync.py`) следит за бригадами на сегодня и ближайшие дни
(по умолчанию 2 дня вперёд). Когда у бригады меняются точки и изменение «устоялось» (~45 секунд без новых правок):

- **нет карты** — создаёт (импорт файла с точками, подпись метки — инвентарный номер, приоритетные — жёлтые);
- **что-то изменилось** — правит карту **точечно** (убирает удалённые точки, перекрашивает/правит описание, добавляет
  новые через поиск по координатам); **ссылка остаётся той же всегда** — карты не пересоздаются. Правок много — они
  делаются порциями (до 40 за одно задание робота), остальное следующим проходом; не вышло — повтор позже, карта не
  пересоздаётся. Карта, чьё содержимое приложение не помнит (ссылку вставили руками), сначала **читается** роботом
  (задание `read`: тексты точек, ничего не меняет), потом правится так же. Новая карта создаётся, только если старой
  уже нет в аккаунте Яндекса (удалили вручную);
- **точка с отчётом о выезде** становится **зелёной** (видно, что осталось объехать — важно для инвентаризации);
- **точек не осталось** или бригаду удалили — карта остаётся как есть и **удаляется только по сроку хранения** (ниже).

Настройки — в календаре: **Настройки → «Яндекс-аккаунт для карт»** (администратор): включить/выключить
автообновление, на сколько дней вперёд вести карты, **автоудаление карт через N дней после даты выезда** — единственный
случай, когда карта удаляется (если галочка снята, карты не удаляются никогда).
Кнопки «🤖 Карты бригад» и «🤖 Создать / обновить карту в Яндексе» (окно «✏️ Изменить» бригады) делают то же вручную.

Карты, в поле ссылки которых лежит заметка (не ссылка Яндекса), автомат не трогает.

## Включение

По умолчанию контейнер **не собирается и не запускается** (профиль compose `robot`: сборка
скачивает браузер ~400 МБ, серверу нужен интернет). Включить на сервере:

```bash
cd docker
docker compose --profile robot up -d --build yandex-robot
```

**Сервер без интернета** (рабочий): образы собираются там, где интернет есть, и переносятся готовыми
архивами — см. `scripts/offline/`: `make_bundle.sh app` — приложение (небольшой, при каждом обновлении;
в нём же свежий **код робота**), `make_bundle.sh robot` — браузер робота (большой, один раз). В каждом архиве
свой `install.sh` и `README.txt`. Код робота подключается к контейнеру из папки проекта `robot/`
(см. `docker-compose.yml`), поэтому обновляется вместе с приложением без пересборки образа.

Основное приложение перезапускать не нужно: оно находит робота по имени `yandex-robot:8100`.
Ключ общения приложение создаёт само (`data/robot/.robot_api_key`), порт наружу не публикуется.

## Вход в Яндекс

Один раз, в веб-интерфейсе календаря (администратор): **Настройки → «Яндекс-аккаунт для карт» →
«Войти в Яндекс»**. Откроется окно с экраном браузера робота (кадры приходят потоком, клики и клавиши
передаются роботу) — вход делается как на сайте Яндекса (в том числе подтверждение по SMS и проверка
«Вы не робот»). Пароль нигде не сохраняется: в профиле робота (том `robot_profile`) остаётся только сессия.
Поток экрана включается только пока окно открыто. Выйти: «Выйти из аккаунта» там же.

## Если не получилось

Ошибка показывается в окне (не вошли / капча / страница изменилась); автомат при сбое повторяет с паузой
и показывает последнюю ошибку в настройках. При сбое робот сохраняет снимок страницы — администратор видит
ссылку «снимок страницы робота». Селекторы Конструктора (кнопки `button_id_importBtn`/`button_id_saveBtn`,
поиск «Адрес или объект», окно точки, список карт `.map-selection-item`) собраны в `constructor.py` — если
Яндекс поменяет вёрстку, правится только он.

Журнал: `docker logs yandex-robot` (робот), `docker logs lan-calendar` (приложение).

## Скачивание фото из таблицы Яндекс Форм

Файлы, приложенные к ответам формы (`https://forms.yandex.ru/cloud/files?path=…`), открываются только создателю формы.
Поэтому приложение («Документы → Отчёты и история выездов → Отчёты из таблицы Яндекс Форм… → Фото») просит скачать их
робота: `POST /download {"url": …}` — браузер робота (под тем же Яндекс-аккаунтом, что создаёт карты) запрашивает файл
со своими cookie и отдаёт байты. Разрешены только адреса Яндекса (https). Нет входа в Яндекс — робот отвечает 409 с
подсказкой «Настройки → Яндекс-аккаунт для карт».
